# JS → Rust parity checklist

What the Electron app (0.1.12) had that the Rust app needed, worked top to bottom and ticked when
done. Kept as a record; the Electron app was removed from the tree in 0.2.0. Compiled from the JS command
registry, menus, UI modules and a 0.1.12 screenshot.

## A. Look & layout (what you see at start-up)

- [x] A1. Icon set: the JS SVG icons (shelf, status line, tool box, outliner, panel toolbar, menus) instead of hand-drawn vector icons / text buttons
- [x] A2. Shelves: same shelf tabs and buttons as `shelf.js` (Curves/Surfaces, Poly Modeling, Sculpting, Rigging, Animation, Rendering, FX, Custom), icon buttons with labels on hover
- [x] A3. Status line: same groups and icons — menu set, new/open/save, undo/redo, hierarchy/object/component mode, selection masks, snap toggles (grid/curve/point/live), history, render/IPR/render settings, input line (Absolute / Relative / Rename / Select) with "x y z or name", Symmetry dropdown, panel toggles on the right
- [x] A4. Tool box: Select, Lasso, Paint, Move, Rotate, Scale, Last Tool; Quick Layout buttons at the bottom (single, four, side by side, outliner + persp, …)
- [x] A5. Workspaces: dock layout remembered between sessions (0.1.12 restores Outliner left + Attribute Editor right from prefs), Workspace selector on the right of the menu bar, workspaces (Maya Classic, Modeling Standard/Expert, Sculpting, Animation, Rigging, Rendering, UV Editing)

## C. Behaviour differences to check

- [x] C1. Hotkeys: compare every JS hotkey (F2–F6 menu sets, Alt+B, Ctrl+Space, B, V, J, Shift+D, Ctrl+Shift+click to shelf, …)
- [x] C2. Preferences persisted to a prefs file (JS stores menu set, workspace, HUD, shelves, hotkeys)
- [x] C3. Viewport visuals: pre-selection highlight, component colours, wire colours, selected-face colour as in JS; component-mode edges keep the JS hilite blue and a hilited-but-unselected curve uses the hilite wire colour; HUD frame shows two decimals (JS `fmt(frame, 2)`); resolution/film gate masks, borders and labels match `drawGate`; Frame Selection frames selected components and falls back to Frame All when its box is empty, and an empty frame uses the JS ±6 box and the JS orthographic aspect factor; Frame All only unions visible mesh/curve/light/locator/camera objects and never the startup cameras (JS `frameAll`); shaded materials use the JS `polygonOffset(1, 1)` so depth-tested wires sit on their surface without a clip-space bias that would reveal hidden back edges at the default camera distance
- [x] C4. Channel Box: MMB virtual slider in viewport, Ctrl/MMB drag in fields, expressions (`+=2`), int/enum stepping
- [x] C5. Component selection: switching vertex/edge/face converts the selection with the JS `convertComp` fallbacks (lone vertex → incident edges / faces), and per-object component sets survive a trip through object mode (JS `Sel.setMode`); the component hilite is a separate list from the object selection (`App.hilite`), so object selection changes in component mode leave the edited objects alone, clicking another object hilites it and appends it to the selection, and leaving component mode keeps the hilited objects selected. Undo snapshots component mode, the hilite and the component sets (JS `Undo.snapshot`).
- [x] C6. Camera navigation and framing follow the JS: tumble accumulates the stored Euler angles directly (`r[1] -= dx*0.4`, `r[0] -= dy*0.4`, no pole clamp, rotate order preserved), bookmarks/default views do not reset the rotate order, orthographic Frame parks the camera 1000 units back with `coi = 1000`, Look at Selection also works in orthographic views and unions only selected object bounding boxes, and new cameras start at (0, 2, 10) like JS `createCamera`.
- [x] C7. Viewport icons: light and user-camera wireframes use the JS `lightIcon` / `cameraIcon` geometry (point/directional/spot/area/ambient/sky dome, camera body + lens + reels) and base `WIRE_MATS.icon` near-black (locators `0x10106e`); selection, lead, affected and template colours replace the base colour exactly as `wireMat` does.
- [x] C8. Shading: per-object X-Ray (Attribute Editor ▸ Render Stats, saved in scene JSON and undo, `setAttr xray`) blends at `min(opacity, 0.5)` with depth write off like JS `prepareScene`; backface culling is one global `App.backfaceCulling` switch mirrored into every pane (toggle, menus, toolbar and picking); default lighting uses the JS `defaultLight` surface-to-light vector `normalize(-0.15*right + 0.2*up - cam_dir)`; each object's x-ray affects rendering only, not `occluded()`.
- [x] C9. Sky dome lights: with Use All Lights the last visible `skyDomeLight` becomes the environment and, when `showBackground` is on, the viewport background is an equirect sampled by the view ray (zenith/horizon/ground, exposure and sRGB like the JS); it is excluded from the punctual light list. `textureFile` decodes HDR/EXR (linear) and PNG/JPG (sRGB, like `loadSkyTexture`), applies the light colour tint, and uses the image for the background, a CPU-prefiltered diffuse irradiance map (the PMREM roughness-1 term `scene.environment` feeds to diffuse shading), and a roughness-selected specular reflection from the sky mip chain. While the file is missing or fails to decode the JS `proceduralSky` fallback is used and a warning is printed; the Attribute Editor file field has a browse button like the JS `type: 'file'` row. The active panel's own camera icon is not drawn, like `n !== this.camNode` (startup cameras were already hidden). Deviations: loading is synchronous (the JS loads in the background), the image is capped at 2048 wide, and the roughness mips approximate the PMREM specular convolution instead of convolving separate GGX lobes.
- [x] C10. Hardware Texturing: `Shading > Hardware Texturing` (6) samples the material maps per fragment from a 64-layer texture array with a full mipmap chain and trilinear minification like three.js (procedural checker/grid/ramp/noise rendered like `proceduralCanvas`, file textures loaded from the project or an absolute path and resized), with each texture's own JS UV transform (`repeatU/V`, `offsetU/V`, `rotateUV`, matching three.js `Matrix3.setUvTransform`; procedural textures bake their repeat into the generated image like the JS). The colour map uses the `white * base/diffuse` tint; the non-colour maps assigned by `applyAttrs` are sampled too: Standard Surface `specularRoughness` (G), `metalness` (B), `emissionColor` (RGB with `max(emission, 0.0001)`), `opacity` (G) and `bump` (R), and Blinn/Phong/Lambert `incandescence`, `transparency` (G), `specularColor` (RGB, Blinn/Phong) and `bump`. Roughness/metalness multiply the material values, an emissive map replaces the flat emission with the map times the emission factor, an alpha map multiplies opacity and puts the mesh in the sorted transparent pass, a specular map tints F0, and a bump map perturbs the shading normal with `bump` as the scale. `colorSpace: Raw` keeps the file's stored linear values (the bytes are pre-encoded into the sRGB array so the GPU decode returns the original value), while the default sRGB files decode normally; shaded mode draws the flat `matsU` colour instead of the texture's average tone, and per-face materials pick their own map. Deviations: textures beyond the 64 array layers fall back to flat colour.
- [x] C11. Shadows: `Lighting > Shadows` and the toolbar toggle enable depth-map shadows only with Use All Lights, matching `renderer.shadowMap.enabled = o.shadows && o.lighting === 'all'`; per-light `shadows` / `shadowRadius` (default 2) and per-mesh Render Stats Casts / Receive Shadows (default on) are saved in the scene. Directional lights use the JS ±25 orthographic shadow camera, spots use `fov = 2 * angle`, point lights render six 90° cube faces, and sampling uses the three.js bias / normalBias, linearly filtered comparison sampling and the r186 five-tap Vogel-disk PCF rotated by interleaved-gradient noise (the JS `shadowRadius` is rescaled from the JS 2048² map so the world-space softness matches); the hardware renderer enables shadows like the JS render view and allocates its depth array at the Render Settings `hwShadowMap` size (512–8192, default 2048), with only the layers the frame's lights need. Deviations: the interactive viewport uses one 512² × 48-layer depth array shared by all lights (the JS viewport defaults to 512² per light), and the hardware array is capped at those 48 layers. Area lights cast no shadows, which matches three.js (RectAreaLight has no shadow camera).
- [x] C12. Menu interaction: every menu bar (main, Outliner, Attribute Editor, viewport panels, Render View, UV Editor) opens on mouse press, follows hover between its own top-level titles while open, highlights the row under the cursor, and runs that row when the button is released, like JS 0.1.12 and Maya; the hotbox keeps its press-open behavior and deliberately does not hover-switch.
- [x] C13. Shading model: the viewport and hardware renderer shade materials like the JS `MeshPhysicalMaterial` — Standard Surface `metalness` removes diffuse and tints F0 by `baseColor`, `specular`/`specularColor` and `specularIOR` drive Fresnel F0 (`min(((ior-1)/(ior+1))² * specularColor, 1) * specular`), and direct lights use a GGX microfacet lobe with the JS `F90 = mix(specularIntensity, 1, metalness)`; Blinn/Phong convert with the JS `applyAttrs` formulas (`sqrt(eccentricity)`, `sqrt(2/(cosinePower+2))*1.2`, `lum(specularColor)` intensity and a specular tint normalised to an average of 1), and the default light uses the JS white × π radiance. The sky environment adds a roughness-mip specular reflection. Standard Surface `coat`/`coatRoughness` add the three.js clearcoat GGX lobe (F0 0.04, F90 1, roughness clamped to 0.0525) and attenuate the base by `1 - coat * Fcc`; `sheen`/`sheenColor` add the Charlie/Neubelt sheen lobe with the three.js sheen albedo energy compensation (the colour is premultiplied by the amount and the JS leaves `sheenRoughness` at 1.0). Area lights use a representative point clamped to the rectangle, reproducing the JS constant radiance and `A * cos(light) / r²` falloff instead of the LTC evaluation. Standard Surface `transmission` samples a copy of the resolved opaque colour through the refracted exit ray (`thickness` 0.5, or 0 for thin-walled materials, like `applyAttrs`) and composes `totalSpecular + mix(totalDiffuse, (1 - F) * diffuseContribution * transmitted, transmission)` in a second depth-loaded pass; the copy is taken before selection overlays, so only opaque geometry and the background are refracted. Deviations: the path tracer evaluates coat/sheen for direct lights and adds a clearcoat reflection on indirect bounces (its base BRDF remains a Blinn-Phong approximation); the viewport transmission copy is an 8-bit sRGB copy decoded in the shader (three.js uses a HalfFloat working-colour target), so a hardware render with tone mapping enabled re-tone-maps the refracted background; the frame buffer holds 32 punctual lights (the JS has no cap); the area-light approximation ignores the LTC horizon clipping and smooth term.
